# Dust Sweeper Analytics — Google Sheets setup

This project includes a private conversion dashboard at:

`https://dustsweepertool.com/admin/analytics`

The analytics backend uses a Google Sheet. It intentionally does **not** store wallet addresses, token contract addresses, private keys, seed phrases, or exact wallet holdings.

## What is measured

Main Dust Finder funnel:

1. Session
2. Finder scan started
3. Scan result returned
4. Assets found
5. Recovery asset selected
6. LI.FI route available
7. Recovery completed

This ultra-conservative build tracks only the core Dust Finder conversion funnel, plus anonymous source/referrer, device, browser language, route status, LI.FI tool and selected recovery chain. It intentionally does not instrument the Wallet, Bridge, Swap or Scam Scan flows.

## 1. Create a Google Sheet

In Google Drive create a blank Google Sheet. Recommended name:

`DustSweeper Analytics`

Do not create columns manually.

## 2. Open Apps Script

From the spreadsheet:

`Extensions -> Apps Script`

Delete the default code and paste the complete contents of:

`google-apps-script/Code.gs`

Save the project.

## 3. Run setupAnalytics

At the top of Apps Script choose the function:

`setupAnalytics`

Click **Run**.

Google may display an authorization warning because this is your own private Apps Script. Review the permissions and authorize the script for the spreadsheet.

The function creates the `Events` tab and generates a private shared secret.

Open the execution log. You will see:

`ANALYTICS_SHARED_SECRET=...`

Copy the value after the equals sign and keep it private.

If you need to see it again later, run:

`showAnalyticsSecret`

Do not run `setupAnalytics` again just to retrieve the secret.

## 4. Deploy as a Web App

In Apps Script:

`Deploy -> New deployment -> Web app`

Use:

- **Execute as:** Me
- **Who has access:** Anyone

Deploy.

Copy the Web App URL. It must end in `/exec`.

Opening that URL in a browser should return JSON similar to:

`{"ok":true,"service":"Dust Sweeper Analytics Google Sheets backend"}`

## 5. Add Vercel environment variables

In the Dust Sweeper Vercel project open:

`Settings -> Environment Variables`

Add:

### ANALYTICS_SHEETS_WEB_APP_URL

Value: the Apps Script `/exec` URL.

### ANALYTICS_SHARED_SECRET

Value: the secret generated by `setupAnalytics()`.

### ANALYTICS_DASHBOARD_PASSWORD

Choose a strong password. This is the password used to open `/admin/analytics`.

The existing `ALCHEMY_API_KEY` remains unchanged.

## 6. Redeploy

After adding the variables, create a new Vercel deployment so the new environment variables are available to the application.

## 7. Test

Recommended first test:

1. Open Dust Sweeper.
2. Run one Dust Finder wallet scan.
3. If assets are found, select an asset.
4. Let the route check complete.
5. Open the `Events` tab in Google Sheets and confirm new rows were added.
6. Open `/admin/analytics` and enter the dashboard password.

A single visitor creates multiple rows because each row is one stage/event of the funnel. The dashboard deduplicates the main funnel by anonymous session ID.

## Traffic attribution

This ultra-conservative build leaves the existing Dust Sweeper URL-cleaning middleware completely unchanged. That means campaign query parameters that the current middleware removes are not persisted by the analytics code.

The dashboard can still record the browser referrer/source when available. If readable Google Ads campaign names become important later, UTM persistence can be added as a separate, isolated change after the core dashboard has been validated.

## Privacy and safety

The analytics layer is deliberately separated from the product flow:

- analytics errors do not block wallet scans;
- analytics errors do not block LI.FI routes;
- analytics errors do not block swaps, bridges or recovery execution;
- no wallet address is sent to the analytics endpoint;
- no token contract address is sent to the analytics endpoint;
- no private key or seed phrase is ever collected;
- exact wallet/token amounts are not stored by this analytics layer.

The Google Sheet should remain private.
